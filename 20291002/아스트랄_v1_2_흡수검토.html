2026-10-07 · 대상: 룰베이스_v5/hubroom_predictor.py (OHT 가감점 포함 운영본) · 자료: V4/아스트랄_결과파일/
아스트랄 FAB 위험 룰 v1.2 는 통째로 쓰지 않는다. 9/12~9/15 에 M14A 경고만 하루 688분이 나오는 등 경보가 너무 많아 오탐 줄이기와 반대다. 대신 룰 아이디어 5가지와 도메인 지식 6가지를 하나씩 우리 예측기에 넣고 8/11~9/15 데이터로 전후를 비교해 좋아진 것만 운영에 넣는다. 오탐에 가장 직접적인 것은 MAXCAPA 이중 가점 정리(도메인 ①)와 점수 합치는 방식(후보 3), 놓친 사건에는 무언정지 룰(후보 1)이다.

2. 흡수 후보 — 도메인 지식 (HUBROOM_domain.md)

현장 설명으로 확정한 지표 의미 중 우리 예측기 룰과 직접 부딪히는 것만 골랐다. 코드는 직접 확인했다.

#도메인 사실우리 예측기 지금영향제안
①MAXCAPA 감소는 작업자 조치일 수 있다. 집계 MAXCAPA 는 절대 상한이 아니고, 6ABL 3F AI 는 TOTALMAXCAPA 280 예외가 있다. "조치 자체에 무조건 장애 점수를 주지 않는다"MAXCAPA 가 기준 이하로 내려가면 영역 점수 +10 그리고 통합 점수에 mc_score +10 을 따로 더한다 → 1개당 raw +20 (ALL 약 +9점). 기준: 3F_LFT ≤100, M14BLFT ≤50, CNV ≤80, M14 CNV ≤150, M16A 2F ≤40, 6F ≤100오탐 원인 후보. 작업자가 계획적으로 MAXCAPA 를 낮추면 장애 없이 점수가 오른다이중 가점 정리 + 실제 반송 영향(반송시간 · PIO · 큐)이 같이 있을 때만 가점 → 데이터로 비교
②AVGTOTALTIME1MIN = 완료된 OHT CMD 의 집기→내려놓기 시간. 완료가 없는 1분은 0. "0 을 정상으로 단정하지 않는다". 정체 해소 뒤 긴 CMD 가 끝나면서 뒤늦게 튈 수 있다R-A 는 이 값이 임계(M16HUB 9분 등) 이상일 때만 걸린다. 0 은 그냥 낮은 값으로 본다심한 정체(데드락 · 무언정지) 중에는 완료가 없어 R-A 가 안 걸리고, 풀린 뒤에 늦게 걸린다후보 1(무언정지)과 묶어 "반송시간 0 + 큐 남음" 을 위험 신호로. 0 연속을 판단불가/주의로 표시
③MLUD 유입은 MMDM 기준(작업자 수동)으로 바뀐다. MLUD 비중 급변이 장비 이상인지 정책 변경인지 데이터만으로 구분 못 할 수 있다R-D 안에 MLUD 잡 ≥ 50 또는 수동 이동 ≥ 30 이면 +7MMDM 기준을 올리면 장애 없이 R-D 가 걸릴 수 있다MLUD 단독 가점 대신 PIO(MLUD AI) · 적재 OHT 동반 시에만
④6ABL6031/6032 는 한 호기가 CNV(6ACNVB01) 출고, 다른 호기가 OHT 출고로 운용될 수 있다. 호기별 물량 불균형은 운용 모드 차이일 수 있다R-C' 는 리프터별 20분 역증가 개수 ≥ 기준이면 +8모드 차이로 생긴 불균형이 역증가로 잡힐 수 있다6031/6032 를 R-C' 에서 따로 보거나 제외해 비교
⑤Sorter 물량만으로 FAB 위험에 가점하지 않는다. 층간 · PIO · 반송 지연이 같이 있을 때만 반송 지표로 반영. 일반 Sorter 와 CU Sorter 는 다른 장비Sorter 대기 기준 이상이면 영역 +3, 통합 sorter_score +3 (역시 두 번)작지만 오탐 쪽으로 더해진다단독 가점 제거 또는 동반 조건 → 비교
⑥평가 원칙. 설계(8/11~9/11)와 평가(9/12~9/15)를 나누고, 시점 t 까지 자료만 쓰는 순방향 재생. 메신저 대화로 사건 목록을 먼저 만들고, 대화 없는 구간 경보는 바로 오경보로 세지 않고 '검토 대상' 으로성능평가.py 는 반송시간(R-A) 기준 대리 정답을 쓴다 — R-A 가 룰 입력이라 독립 정답이 아니다지금 오탐률 숫자가 실제보다 좋거나 나쁘게 보일 수 있다운영로그_분석_v2 Episode 라벨을 정답으로 연결해 평가 (README 의 '예정' 항목)

그 밖에 참고: HUBROOM = bridge = M14HUB = M16HUB (같은 공간), M16 3F = M14 측 4F, 4AFC3201 남측 · 4AFC3301 북측 CNV, CURRENTQCREATED/COMPLETED 는 최근 10분 MCS JOB 집계라 다시 10분 합산하면 안 된다, M16A.QUE.ALL.CURRENTQCNT 는 2F·3F·6F 전체라 6F 신호가 아니다, HUB STB_CMD 는 STB 로 가는 모든 사유 포함(MAXCAPA 제한 지표 아님), 계획 작업(OHT STOP · OSS ON/OFF)은 장애와 따로 표시.

4. 후보별 산식 (아스트랄 원문)

숫자(8%p, 0.3 등)는 아스트랄 후보값이라 우리 데이터로 다시 정한다. S(x) = 0~1 위험 강도, D = 반송 지연, Q = 현재 물량, G = 10분 증가율, F = 생성 대비 완료 부족.

1. 무언정지 (처리 감소와 대기 증가, 최대 85점)

기준완료 = 중앙값( t−39 ~ t−10 분의 최근10분 완료값 ) ※ 유효 20개 이상
L = S( max(0, 1 − 현재완료10 ÷ 기준완료) )
점수 = 85 × min( L, max(G, F, D) ) ← 완료가 줄고 + 물량·부족·지연 중 하나가 같이 있어야

2. OHT 가동률 급락 · Queue 급증 (40~70점)

조건: 직전 5분 중앙값 대비 가동률 하락 ≥ 8%p 그리고 Queue 증가 ≥ 5%
u = clip((하락폭 − 8) ÷ 12, 0, 1), q = clip((증가율 − 0.05) ÷ 0.10, 0, 1)
점수 = 40 + 30 × min(u, q) ※ 가동률 하락 단독은 0점

3. 점수 합치는 방식

룰 점수를 큰 순으로 r1 ≥ r2 ≥ r3
기본점수 = min(100, r1 + 0.30×r2 + 0.15×r3)
안정화: 3분 중앙값 · 하락은 분당 최대 5점 · 강한 룰(처리감소 ≥70, 급락 ≥40)은 즉시 상승

4. 판단불가

필수 입력 결측 → 등급 '판단불가' + 품질.파생값관측률(활성 파생값 중 관측 비율) 별도 출력. 결측을 0 으로 계산하더라도 '결측 = 정상' 으로 보지 않음

5. 임계 초과 정도

S(x) = clip((x − L) ÷ (H − L), 0, 1), L = 설계구간 P90, H = P99 (PIO 는 P99.5)
예) 반송 지연 = 45 × max( S(완료시간 3분 중앙값), S(4분 초과율 3분 중앙값) )
