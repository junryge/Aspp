안내

이 문서의 범위

실시간 관제(AMHS SENTINEL)를 띄우고, 설정하고, 배포하고, 문제를 푸는 방법입니다. 화면 사용법은 사용자 매뉴얼에 있습니다.

관제 폴더
scientific-assistant/real_time_amhs/ — 이하 관제. 서버 server.py, 화면 static/, 설정 config.json, 자료 data/.
월드모델파생 폴더
real_time_amhs/월드모델/월드모델파생/ — 이하 월드모델파생. OHT 재생 서버 main.py(포트 10005, 8장), UI대쉬보드 원본 OHT_Bridge_Monitor.html · bridge_editor.js.
원본 월드모델
WORD_MODEL/WORLD_SIM/ — 파생의 뿌리. 운영에는 쓰지 않습니다.

제일 중요한 세 가지

① 배포는 파일 단위 교체입니다. data/ · config.json · 키 파일 · 설정 JSON 은 덮어쓰지 않습니다 (9장).

② 비밀(키·비밀번호)은 저장소 파일에 적지 않습니다. 숨김 비밀번호는 해시로만 들어 있습니다 (4장).

③ 테스트는 운영 폴더에서 돌리지 않습니다 — 일부 테스트가 data/ 에 파일을 씁니다 (11장).

1

만들어진 경위

실시간 관제는 OHT 월드모델에서 파생되어 만들어졌습니다. 월드모델 작업에서 나온 룰베이스 예측기의 점수를 실시간으로 받아 보여 주는 것이 관제이고, 관제에서 찾은 시각은 다시 월드모델로 돌아가 OHT 움직임으로 확인합니다.

그래서 운영에서 챙길 것

관제가 받는 파일의 모양(컬럼·파일 이름 규칙)은 예측기가 정합니다. 예측기가 바뀌면(컬럼 추가·배점 변경) 관제 화면의 칸과 '룰 배점 합 ≠ 저장된 점수' 같은 경고가 먼저 알려 줍니다. 월드모델파생은 관제 폴더 두 단계 아래에 있어야 로그프레소 키·주소를 관제 설정에서 빌려 씁니다 — 폴더 구조를 바꾸지 마세요.

3

기동 · 중지 · 확인

관제는 flask · requests 만 있으면 뜹니다. 월드모델파생은 fastapi · uvicorn · pandas · requests 가 필요합니다.

관제

cd real_time_amhs
pip install -r requirements.txt        # requests, flask
python server.py                       # → http://localhost:8989/  (다른 PC: http://<이 PC IP>:8989/)
  • 켜지면 먼저 모든 시스템의 오늘 00:00~지금을 한꺼번에 확보하고, 그 뒤 60초마다 이어 받습니다.
  • 콘솔 머리에 데이터 출처·모델·폴링 주기·대시보드 주소·사내망 IP 가 찍힙니다. 다른 PC 에서 안 열리면 방화벽에서 TCP 8989 인바운드를 엽니다.
  • 브라우저 자동 실행 끄기: config.json 의 server.auto_open: false 또는 환경변수 NO_BROWSER=1.
  • 중지: 콘솔에서 Ctrl+C. 수집 스레드는 같이 끝납니다. 자동 재시작(리로더)은 없습니다.

월드모델파생

cd real_time_amhs/월드모델/월드모델파생
pip install fastapi "uvicorn[standard]" requests pandas
python main.py                         # → 포트 10005
  • OHT_MAP/MAP/<FAB>/<PREFIX>.layout.zip(맵 재료)이 있어야 합니다 — 저장소에는 캐시(OHT_MAP/cache)만 있고 레이아웃 zip 은 현장에 따로 둡니다.
  • 작업자(worker)를 늘리지 마세요 — 접속자 세션을 프로세스 메모리에 둡니다.
  • 중지: Ctrl+C (임시 조회 캐시 _logpresso_cache/ 는 저절로 지워집니다).
  • 맵 재료 · 키 · exe 빌드 · 로그 · 문제 해결은 8장.

4

설정 (config.json) 과 비밀

설정은 관제 폴더의 config.json 한 장입니다. 정책 탭에서 저장하면 서버가 이 파일을 다시 씁니다. 손으로 고쳤으면 관제를 재시작해야 반영됩니다.

키뜻
source.modejupyter(현재) 또는 logpresso. 주피터 모드일 때만 FAB 다섯 화면이 생깁니다.
source.jupyterbase_url · path(ALL 파일) · fab_path(FAB 파일, {fab} 자리) · fabs(화면 코드 → 파일 접미사 — 시스템 목록이 여기서 나옴) · timeout_s · encoding. 비밀번호 칸은 비워 둡니다.
querypoll_interval_s(수집 주기, 기본 60 · 선택지 10/30/60/300/600) · window · timeout_s · max_retries · use_proxy.
gradebands(경계 60–70 · 위험 71–84 · 초위험 85–100, 설명 글) · alarm(등급 카운터 기본: 10분 · 경계 3 · 위험 1 · 초위험 1). 정책 탭이 grade.by_sys · grade.alarm_by_sys 를 써 넣습니다.
llmenabled · url · model · per_minute(1분 판단: 주기 · 한 번에 메울 수) · accuracy(사후채점 20분 창) · analysis(숨김 탭 4단계 분석). 키 칸은 없습니다(token.txt / 환경변수).
policy에스컬레이션 표(읽기 전용 표시), 억제 창 30분, 케이스 보관 30일. 정책 탭이 policy.auto_tune(LLM 컷 자동 조정, 기본 꺼짐)을 써 넣습니다.
storagedaily_csv_dir(data) · 케이스 · 리포트 · 중복 판정 칸 · retention_days(과거 파일 정리 보관 기간, 0 = 끔 — 정책 탭이 써 넣음, 5장).
serverhost 0.0.0.0 · port 8989 · auto_open.
ui.metric_groups추이 그래프 지표 묶음 — 단추 이름 스코어컬럼 / CSV스코어데이터 컬럼(id 는 amos / csv 그대로). FAB 화면 것은 자동으로 만들어집니다. ALL 화면 이름은 이 칸의 name 두 개에서 나오므로, 현장 config.json 은 그 두 이름만 손으로 고칩니다(2026-09-28 이름 바꿈 — 숨김 모드에서는 ALL 이 가려져 안 보입니다).
fab_score화면에 보여 줄 임계 덮어쓰기(thresholds) 등. 점수는 바꾸지 않습니다(6장).
world_model (파일에 없음)없으면 기본값: enabled true · base ""(화면이 보는 주소의 :10005) · port 10005 · minutes 1 · timeout_s 2. 월드모델이 다른 PC 면 "world_model": {"base": "http://그PC:10005"}.

config.json 을 통째로 갈아 끼우지 마세요

현장 config.json 에는 정책 탭에서 저장한 값(시스템별 컷·알람·LLM 설정)이 들어 있습니다. 새 기능에 설정 키가 필요하면 그 키만 손으로 더하고 관제를 재시작합니다.

  • 점검 명령이 키의 일부(앞 8자 · 끝 4자)를 콘솔에 찍습니다 — 화면 캡처를 공유할 때 가리세요.

숨김 모드 비밀번호 바꾸기

비밀번호는 파일에 SHA-256 해시로만 있습니다(static/dashboard.html 의 HIDE_PW_SHA). 평문은 어디에도 두지 않습니다.

  1. 새 비밀번호의 해시를 구합니다:
    python -c "import hashlib;print(hashlib.sha256('새 비밀번호'.encode()).hexdigest())"
  2. static/dashboard.html 의 const HIDE_PW_SHA = '…'; 값을 위 64자로 바꿉니다.
  3. 그 파일만 교체하고 브라우저를 새로 고칩니다(서버 재시작 불필요). 화면에서 새 비밀번호로 풀리는지 확인합니다.

숨김은 화면 가림이지 보안 장치가 아닙니다 — 서버 API 는 그대로 열려 있습니다.

5

데이터 폴더와 수집

모든 자료는 관제 폴더의 data/ 에 날짜별로 쌓입니다. 전부 실행 중에 생기는 파일이고 저장소에 올라가지 않습니다.

파일내용
data/{YYYYMMDD}_TOTAL.CSVALL — 1분 한 줄 누적. 같은 분이 다시 와도 중복으로 안 쌓입니다.
data/{FAB}/{YYYYMMDD}_TOTAL.CSVFAB 다섯 — 받을 때 FAB 점수(area_score)를 점수 칸으로 옮겨 저장.
…_LLM.CSV · …_ML.CSV1분 LLM 판단과 사후채점 · ML 조기예측(ALL).
raw/받은 원본(받을 때마다 덮어씀).
cases.json · cases_old/ · reports/ · analysis/케이스 · 30일 지난 케이스 보관 · 리포트 · 분석.
feedback.jsonl · score_tune.jsonl피드백 · 컷 자동 조정 기록.

수집 동작 (주피터 모드)

  • 60초(수집 주기)마다 6개 시스템을 동시에 받습니다.
  • 꼬리받기 — 이미 가진 파일의 끝부분만 이어 받고, 10번에 1번은 전체를 다시 받아 빠진 분을 메웁니다.
  • 주피터 로그인은 10분 재사용합니다. 403 이 오면 한 번 다시 로그인합니다.
  • 오늘 파일이 아직 없으면 가장 최근 날로 물러서고, 화면에 '실시간이 아닙니다' 경고를 띄웁니다.

콘솔에는 이런 줄이 찍힙니다 — "받기" 가 크면 주피터 쪽, "저장" 이 크면 관제 쪽이 느린 것입니다.

과거 파일 정리 (보관 기간)

날짜 파일은 저절로 지워지지 않습니다. 정책 탭의 과거 파일 정리 — 보관 기간 카드에서 기간을 정하면(storage.retention_days, 0 = 끔이 기본) 하루 한 번 — 관제를 켤 때, 그리고 날이 바뀐 뒤 첫 수집 때 — ALL 과 FAB 다섯 폴더에서 기간을 넘긴 날짜 파일을 지웁니다.

  • 지우는 것: {날짜}_TOTAL.CSV · {날짜}_LLM.CSV(설정의 접미사) · {날짜}_ML.CSV · raw/{날짜}_*.csv. 보관 N일 = 오늘 포함 N일을 남김.
  • 안 지우는 것: 케이스 · 리포트 · 분석 · 피드백 · 설정, 이름에 날짜가 없거나 모르는 파일, 달력에 없는 날짜.
  • 저장만으로는 바로 지우지 않습니다. 바로 지우려면 카드의 지금 정리(확인 창). 잠긴 파일은 건너뛰고 다음 정리 때 다시 해 봅니다. 폴더를 새로 만들지 않습니다.
  • 지우는 일은 수집과 따로 돕니다(수집이 밀리지 않음). 콘솔에 이렇게 남습니다:
[정책] 과거 파일 정리 → 보관 30일 · 저장됨
[정리] 하루 한 번 · 보관 30일(20260830 부터 남김) → 900개 · 1072.6MB 지움 (20260402~20260829, 150일치)  [0.1초]

느려지던 것과는 따로입니다

날짜가 쌓일수록 UI대쉬보드 · 과거 조회가 느려지던 원인(날짜 목록이 옛 파일을 매번 처음부터 다시 읽음)은 2026-09-28 에 고쳤습니다 — 이제 안 바뀐 파일은 다시 읽지 않습니다(180일치에서 2.4초 → 0.005초). 보관 기간은 디스크를 위한 것입니다.

점수와 정책이 저장되는 곳

관제는 점수를 새로 계산하지 않습니다. 예측기가 적은 점수를 그대로 쓰고, 등급(색·알람)만 정책 컷으로 매깁니다.

  • 점수 — FAB 파일의 area_score(0~100). 예측기 정의: area_score = min(100, round(raw × 100 ÷ 70)), raw = 룰 배점 합 + PIO 점수.
  • 등급 컷 — 기본은 grade.bands(60/71/85). 정책 탭 '수동 변경' 이 grade.by_sys.{시스템} 에 저장하고 바로 반영합니다(파일은 임시 파일에 쓴 뒤 바꿔 끼움).
  • 등급 카운터(알람) — 정책 탭 → grade.alarm_by_sys.
  • LLM 컷 자동 조정 — policy.auto_tune. 기본 꺼짐. 켜면 2시간마다(홀수 시각), 한 번에 최대 10점. 결과는 변경 로그와 data/score_tune.jsonl.
  • 화면 임계(실제지표 칸의 임계선) — fab_score.py 의 WATCH(컬럼흐름 상세도 기준). 표시용입니다. 바꾸면 python fab_score_doc.py 로 docs/FAB별_위험도_스코어.html 을 다시 만듭니다.

UI대쉬보드 관리

UI대쉬보드는 월드모델파생에서 만든 화면(OHT_Bridge_Monitor.html)을 관제가 static/ 에서 그대로 내주는 것입니다.

파일자리관리
OHT_Bridge_Monitor.html관제 static/ 와 월드모델파생 — 두 벌이 같아야 합니다편집기 코드 bridge_editor.js 가 안에 그대로 박혀 있습니다(시험이 확인).
OHT_Bridge_Monitor_설정.jsonHTML 과 같은 폴더있으면 HTML 기본값 · 브라우저 저장값보다 먼저 적용됩니다. 저장소에 올리지 않습니다(gitignore).
OHT_Bridge_Monitor_배경.webpHTML 과 같은 폴더(두 곳)바탕 그림(SK하이닉스 41주년). 같은 이름으로 갈아 끼우면 바뀝니다. 투명(알파) webp · 600KB 미만. 없으면 그림만 빠집니다.

모두에게 같은 화면 설정을 주려면

  1. 누구든 UI대쉬보드 → ✎ 수정 에서 꾸민 뒤 저장 (JSON) — 그 사람 PC 에 OHT_Bridge_Monitor_설정.json 이 생깁니다(서버에는 안 올라감).
  2. 그 파일을 관제 static/ 에 둡니다(월드모델파생에서 더블클릭으로 볼 때는 그 폴더에도).
  3. 브라우저 새로 고침 — 모든 사람에게 그 설정이 먼저 적용됩니다.

화면을 다시 만들 때 (맵·판 구성 변경)

  1. 월드모델파생 폴더에서 python MAP_아이소_얹기.py — 늘 고객 원본(OHT_Bridge_Monitor_원본.html)에서 만들고, bridge_editor.js 를 그대로 넣습니다. 맵 재료는 OHT_MAP/cache.
  2. 만들어진 OHT_Bridge_Monitor.html 을 관제 static/ 에 복사합니다(두 벌을 같게).
  3. 브라우저 새로 고침(서버 재시작 불필요).

8-3. 로그프레소 키 · 주소

logpresso_query.py 의 API_KEY 는 빈 채로 둡니다. 비어 있으면 아래 순서로 찾아 씁니다 — 월드모델파생이 관제 폴더 두 단계 아래에 있어야 ②가 됩니다.

  1. 환경변수 LP_API_KEY (주소는 LP_HOST · LP_PORT) — 언제나 이깁니다.
  2. 관제의 config.json(api_key · logpresso_base) 또는 api_key.txt — 키를 빌리면 주소도 같이 빌립니다(키와 주소의 짝이 어긋나면 401).
  • 콘솔에 어느 서버에 어느 키로 쳤는지 남습니다 — [접속] <주소>:<포트> remote=… 키 출처 환경변수/관제 설정 (끝 4자 …xxxx). 401 이면 여기부터 봅니다.
  • 조회 형태 기본값 LP_QUERY_PROFILE(raw) 은 화면 밖에서 부를 때만 씁니다 — 화면은 상세/간소를 매번 보냅니다.
  • ★키를 파일에 적어 저장소에 올리면 안 됩니다 (4장 · tests/test_secrets.py).

8-4. 접속자 · 메모리

  • 사람(브라우저 쿠키 oht_sid)마다 재생 · 불러온 자료 · 고른 FAB · 조회 멈춤을 따로 가집니다. 맵(레이아웃 · HID Zone)은 FAB 마다 한 벌만 읽어 같이 씁니다.
  • 한 시간 아무 요청이 없으면 그 사람 몫을 치웁니다(OHT_SESSION_TTL, 초, 기본 3600). 동시에 24명까지 들고, 넘으면 가장 오래 안 온 사람부터 치웁니다(OHT_SESSION_MAX).
  • 상세 30분 조회 하나가 수십만 건입니다(예시 450대 · 10분 = 27만 건). 메모리가 모자라면 OHT_SESSION_MAX 를 줄입니다.
  • 작업자(worker)는 늘리지 않습니다 — 세션이 프로세스 메모리에 있어, 여럿이면 같은 사람이 요청마다 다른 곳에 붙습니다.
