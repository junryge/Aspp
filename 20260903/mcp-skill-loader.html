LLM API 서버 × MCP × Skill

LLM API를 받는 서버가 MCP에서 스킬을 가져와 자동으로 쓰는 구조

호출하는 쪽은 그냥 /v1/chat/completions를 친다. 스킬을 고르고, MCP에서 읽고, 지침대로 실행하는 건 전부 API를 받는 서버 안에서 일어난다. 호출자는 스킬도 MCP도 모른다.

1. 전체 구조 — 스킬 로딩은 API 서버 내부에서

vLLM 같은 추론 엔진은 그냥 텍스트를 넣고 빼는 물건이라 MCP를 직접 붙일 수 없다. 그래서 그 앞에 얇은 LLM API 서버(FastAPI)를 하나 두고, 이 서버가 밖으로는 OpenAI 호환 API를 열고 안으로는 MCP 클라이언트가 된다. 사내에서 "LLM API"라고 부르는 주소가 바로 이 서버다.

Claude API를 쓰는 경우: Anthropic Messages API는 요청에 mcp_servers를 넣으면 API 서버 쪽이 직접 MCP 서버에 붙어 tools를 가져온다(MCP connector). 이게 "API 받는 곳에서 MCP를 쓰는" 공식 형태다. 다만 스킬 본문 로딩은 여전히 tool 호출로 풀어야 하고, 폐쇄망 Qwen에는 해당이 없으니 아래는 직접 만드는 쪽 기준이다.

2. 왜 prompts가 아니라 resources + tools인가

MCP에는 스킬을 실을 수 있는 프리미티브가 세 가지 있다. 셋 다 되지만, 모델이 스스로 골라 쓰게 하려면 어디에 싣는지가 중요하다.

프리미티브원래 용도자동 로딩 관점
prompts사용자가 UI에서 고르는 템플릿 (슬래시 커맨드 성격)사람이 고르는 진입점. 모델 자동 선택용으로는 부적합.
resourcesURI로 읽는 정적 컨텐츠SKILL.md · references/*.md를 skill:// URI로 노출. 카탈로그는 resources/list, 본문은 resources/read.
tools모델이 호출하는 함수run_skill_script로 스킬 스크립트 실행. 파일은 서버 쪽에 두고 결과만 돌려준다.

load_skill은 MCP 서버 tool이 아니라 API 서버가 모델에게 직접 노출하는 가상 tool이다. 모델이 이걸 부르면 API 서버가 MCP resources/read로 바꿔 처리한다. 이렇게 하면 스킬 서버는 파일만 서빙하면 되고, "언제 무엇을 읽을지"는 API 서버 정책으로 남는다.

3. 요청 한 건의 흐름 — progressive disclosure

스킬 전문을 처음부터 다 넣으면 컨텍스트가 터진다. 그래서 두 단계로 나눈다. 처음엔 이름 + 설명만, 모델이 고른 뒤에 본문을 넣는다.

skill_server.py — 스킬 MCP 서버 (stdio)

from mcp.server import Server
from mcp.types import Resource, TextContent, Tool
import mcp.server.stdio, pathlib, subprocess, re

ROOT = pathlib.Path("skills")
srv  = Server("skill-server")

def frontmatter(md):
    m = re.match(r"---\n(.*?)\n---", md, re.S)
    return dict(l.split(":", 1) for l in m.group(1).splitlines()) if m else {}

@srv.list_resources()                      # 카탈로그
async def list_resources():
    out = []
    for d in ROOT.iterdir():
        fm = frontmatter((d / "SKILL.md").read_text(encoding="utf-8"))
        out.append(Resource(uri=f"skill://{d.name}/SKILL.md",
                            name=fm.get("name", d.name).strip(),
                            description=fm.get("description", "").strip(),
                            mimeType="text/markdown"))
    return out

@srv.read_resource()                       # 본문 (references/*.md 도 동일 경로 규칙)
async def read_resource(uri):
    return (ROOT / str(uri).removeprefix("skill://")).read_text(encoding="utf-8")

@srv.list_tools()                          # 스킬 스크립트 실행
async def list_tools():
    return [Tool(name="run_skill_script",
                 description="스킬 폴더의 scripts/ 안 파이썬 스크립트를 실행한다",
                 inputSchema={"type":"object","properties":{
                     "skill":{"type":"string"},"script":{"type":"string"},
                     "args":{"type":"array","items":{"type":"string"}}},
                     "required":["skill","script"]})]

@srv.call_tool()
async def call_tool(name, a):
    p = ROOT / a["skill"] / "scripts" / a["script"]
    r = subprocess.run(["python", str(p), *a.get("args", [])],
                       capture_output=True, text=True, timeout=120)
    return [TextContent(type="text", text=r.stdout or r.stderr)]

async def main():
    async with mcp.server.stdio.stdio_server() as (r, w):
        await srv.run(r, w, srv.create_initialization_options())

llm_api.py — LLM API 서버 (FastAPI, OpenAI 호환 · 안에서 vLLM + MCP)

from fastapi import FastAPI
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client
import httpx, json

VLLM = "http://vllm:8000/v1/chat/completions"      # 실제 추론 엔진
app  = FastAPI()
S    = {}                                            # mcp 세션, 카탈로그, tools

LOAD_SKILL = {"type":"function","function":{"name":"load_skill",
  "description":"카탈로그의 스킬 본문(SKILL.md)을 읽어온다. 해당 작업 전에 반드시 호출.",
  "parameters":{"type":"object","properties":{"name":{"type":"string"}},"required":["name"]}}}

@app.on_event("startup")                      # 기동 시 1회: MCP 붙고 카탈로그 캐시
async def boot():
    r, w = await stdio_client(StdioServerParameters(command="python", args=["skill_server.py"])).__aenter__()
    mcp = await ClientSession(r, w).__aenter__(); await mcp.initialize()
    res = (await mcp.list_resources()).resources
    S["mcp"] = mcp
    S["system"] = "사용 가능한 스킬:\n" + "\n".join(f"- {x.name}: {x.description}" for x in res) \
                + "\n작업에 맞는 스킬이 있으면 먼저 load_skill 로 읽고 그 지침을 따른다."
    S["tools"] = [LOAD_SKILL] + [{"type":"function","function":{"name":t.name,
                  "description":t.description,"parameters":t.inputSchema}}
                  for t in (await mcp.list_tools()).tools]

@app.post("/v1/chat/completions")            # 호출 앱이 보는 유일한 엔드포인트
async def chat(body: dict):
    msgs = [{"role":"system","content":S["system"]}] + body["messages"]
    async with httpx.AsyncClient(timeout=300) as hx:
        while True:
            out = (await hx.post(VLLM, json={"model":body.get("model","qwen3"),
                        "messages":msgs,"tools":S["tools"]})).json()
            m = out["choices"][0]["message"]
            msgs.append(m)
            if not m.get("tool_calls"):
                return out                                 # ⑧ 최종 답만 반환
            for tc in m["tool_calls"]:
                fn, args = tc["function"]["name"], json.loads(tc["function"]["arguments"])
                if fn == "load_skill":                        # ③④⑤⑥
                    rr = await S["mcp"].read_resource(f"skill://{args['name']}/SKILL.md")
                    text = rr.contents[0].text
                else:                                          # ⑦ run_skill_script 등
                    rr = await S["mcp"].call_tool(fn, args)
                    text = "\n".join(c.text for c in rr.content)
                msgs.append({"role":"tool","tool_call_id":tc["id"],"content":text})

6. 폐쇄망에서 챙길 것

세 프로세스 전부 pip install mcp fastapi httpx로 끝난다. 스킬 서버는 stdio라 포트를 안 열고, API 서버가 자식 프로세스로 띄운다. 스킬 폴더는 base64로 옮겨 넣고 API 서버를 재시작하면 카탈로그에 반영된다. Oracle·Logpresso 접속 정보는 스킬 서버 프로세스 환경변수에만 두면 모델 컨텍스트에도, 호출 앱에도 절대 안 실린다.

호출 앱 쪽은 바꿀 게 없다. 기존에 vLLM을 직접 치던 주소를 이 API 서버로 바꾸기만 하면 스킬이 자동으로 붙는다. 스킬이 30개를 넘어가면 system에 전부 넣지 말고 search_skill(query) tool을 하나 더 두고 description으로 검색시키는 게 컨텍스트에 유리하다.
