1왜 이식했나#

원본은 TypeScript 모노레포 4패키지 + Python 커널 런타임이다. Windows 폐쇄망에서 막히는 지점이 6군데다.

2아키텍처#

2.1프로세스 구조#

원본의 3프로세스(슈퍼바이저 · 워커 · 커널)를 단일 프로세스 + 스레드 + 커널 1개로 접었다. "한 워커가 root 세션과 그 아래 RLM 자손 전부를 소유한다"는 원본의 소유권 규칙은 그대로다.

2.2호스트 브리지#

원본은 워커(TS) ↔ 커널(Python) 을 Jupyter comm host.request 로 잇는다. 이식본은 호스트도 Python 이므로 loopback TCP + 줄단위 JSON + 토큰 인증으로 단순화했다.

Windows 에서 named pipe·유닉스 소켓을 신경 쓸 필요가 없고, 커널이 별도 프로세스라 모델이 커널을 죽여도 호스트가 살아남는 원본의 성질도 유지된다.

원본과 같은 방어 하나를 그대로 옮겼다 — 요청 직렬화 시 payload 를 먼저 펼치고 type 을 나중에 넣는다. payload 안의 type 키가 요청을 가로챌 수 없게.

msg = {"payload": payload or {}, "rid": rid, "token": _TOKEN, "type": rtype}

3.1의존 방향#

cli ──▶ agent ──▶ provider ──▶ (HTTP)
          │  ├──▶ kernel ──▶ (IPython 프로세스) ──▶ kernel_runtime/rlm
          │  ├──▶ harness
          │  ├──▶ skills
          │  └──▶ session
          └──▶ config  (전부가 참조)

순환 없음. kernel_runtime/rlm 은 호스트 코드를 import 하지 않는다 — 커널 프로세스에만 올라간다.

4실행 흐름#

1  사용자 입력            cli.main() → AgentSession.run_turn(text)
2  컴팩션 판정            maybe_compact() — contextTokens > contextWindow - reserveTokens
3  컨텍스트 구성          SessionManager.build_context() — leaf→root 경로, compaction 반영
4  시스템 프롬프트 조립    기본 + 자식 독트린 + 스킬 목록 + 하네스 + AGENTS.md + goal
5  모델 호출              provider.stream_completion() — SSE, on_delta 로 스트리밍
6  분기
   ├ 툴 콜 없음  →  루프 종료
   └ 툴 콜 있음  →  kernel.execute(code) → toolResult append → 2번으로
7  턴 경계 후처리         예약된 compact 실행 → 인박스 배수 → 예약된 refine 실행

턴 경계 규칙(원본과 동일): 컴팩션과 정제는 셀 중간에 절대 돌지 않는다. 커널에서 await compact.run() / await refine.run() 을 부르면 예약만 되고, 현재 턴이 끝날 때 호스트가 실행한다.

5원본에서 그대로 옮긴 규칙#

이식하면서 의도적으로 보존한 동작들이다. 고칠 때 여기를 깨지 않게 조심해야 한다.

규칙 구현 위치
rlm(...) 은 admission 시점 반환. 자식 답변을 절대 반환하지 않음 agent.py::_h_rlm_run
자식 결과는 agent_message 나 파일로만 설계 + 시스템 프롬프트
run() 지원 옵션은 name/model/thinking 3개뿐, 모르는 옵션은 실패 rlm/__init__.py::_RLM.run
요청 모델을 못 쓰면 조용히 대체하지 않고 spawn 실패 agent.py::_h_rlm_run
재귀 깊이 기본 2 (root→자식→손자). Python 과 호스트 양쪽에서 검사 rlm/__init__.py + agent.py
메시징 범위는 부모·형제·직계 자식. 발신자 신원은 호스트가 정함 agent.py::_family
receiver_name 은 sibling/child 에 필수, parent 에는 금지 rlm/__init__.py::_AgentMessage.send
기본 시스템 프롬프트 불변 — base_system_prompt id 하드 거부 harness.py::HarnessStore.upsert
skill 엔트리는 reference.type == "python" + import + callable/call_pattern + arguments 필수 harness.py::_validate_skill_reference
update 시 생략된 path/reference/arguments/metadata 는 보존, 명시값({} 포함)은 덮어씀 harness.py::upsert
refine 은 역순 재생으로 롤백 harness.py::rollback
손상된 refinements.jsonl 한 줄이 롤백 전체를 막지 않음 harness.py::history
하네스 상태는 mtime 이 바뀌면 다시 읽음 (커널·호스트 동시 쓰기 방어) harness.py::_sync
컴팩션 컷 포인트는 툴 결과에서 자르지 않음 agent.py::compact
goal.complete() 만이 성공 완료 신호 agent.py::_h_goal_complete
autonomous 판정 순서 게이트 먼저 → 연속 → 턴 → 토큰 → 시간 cli.py::run_autonomous
게이트 통과는 한도 도달을 무시하고 완료 허용 cli.py::run_autonomous
변경 없이 실패한 게이트는 재실행하지 않고 시도 횟수만 증가 cli.py::run_autonomous
description 없는 스킬은 로드하지 않음 skills.py::load_skill
Python 스킬 4조건 미충족 시 마크다운으로 조용히 강등 + 경고 skills.py::load_skill
스킬 import 실패가 커널을 깨뜨리지 않음 (호출 시 원래 에러를 담은 RuntimeError) kernel.py::_bootstrap
run() 가진 스킬 모듈은 async callable 로 래핑 kernel.py::BOOTSTRAP
이름 충돌 시 처음 찾은 스킬 유지 + 경고 skills.py::discover
자식 usage 를 부모 assistant 턴에 귀속 (child_usage_attributed) agent.py::_h_rlm_run

6커널 API#

커널 부트스트랩이 만드는 네임스페이스. sys.modules["rlm"] 는 패키지로 남아 저장소 스킬의 from rlm import host_request 가 그대로 동작한다.

6.1rlm#

handle = await rlm("독립 하위 작업", name="reviewer", model="internal/Qwen3-32B",
                   thinking="medium")
# → RLMSpawnHandle(rlm_child_id, name, session_dir, model)   ※ 자식 답변 없음

await rlm.find_models(query="", limit=8)      # [RLMModel(provider,id,name,selector)]
await rlm.list_subagents()                    # [RLMSubagent(..., status)]
await rlm.delete_subagent("reviewer")         # 툼스톤. 디스크 트랜스크립트는 안 지움
await rlm.host_request("사용자정의.요청", {...})

병렬은 "여러 번 호출하고 턴을 끝내는 것". rlm.background 는 존재하지 않는다(원본과 동일).

6.2agent_message / agent_observe#

await agent_message.list_agents()             # {current, entries[relationship,name,id,depth,status]}
await agent_message.send("결과", receiver_role="parent")
await agent_message.send("확인해라", receiver_role="child", receiver_name="reviewer")
await agent_message.send("all", "전체 공지")   # 브로드캐스트 → {receipts:[...]}

await agent_observe.recent_messages("reviewer", limit=8, max_chars=800)   # 읽기 전용

배송 상태는 delivered(유휴 대상 도달) 또는 queued(실행 중이라 대기). send 는 블로킹하지 않는다. send 직후 자식을 삭제하지 마라 — 배달된 follow-up 이 아직 돌고 있을 수 있다.

6.3harness#

await harness.overview()
await harness.list(kind="memory", global_=False)
await harness.create_memory("배포 규칙", "릴리스는 금요일에 하지 않는다", global_=True)
await harness.update_prompt_note("보고 형식", "표부터 제시할 것")

Python 예약어 때문에 global=True 는 문법 오류다 → global_=True.

7.2models.json#

원본 스키마와 호환된다.

{
  "providers": {
    "internal": {
      "name": "사내 추론",
      "baseUrl": "http://10.0.0.42:8000/v1",
      "api": "openai-completions",
      "apiKey": "INTERNAL_LLM_KEY",
      "authHeader": true,
      "headers": { "X-Corp-Auth": "CORP_TOKEN_ENV" },
      "compat": {
        "supportsDeveloperRole": false,
        "supportsReasoningEffort": false,
        "supportsUsageInStreaming": true,
        "maxTokensField": "max_tokens"
      },
      "models": [{
        "id": "Qwen/Qwen3-32B",
        "name": "Qwen3 32B",
        "reasoning": true,
        "input": ["text"],
        "contextWindow": 262144,
        "maxTokens": 32768,
        "compat": { "thinkingFormat": "qwen-chat-template" }
      }]
    }
  }
}

apiKey·headers 값 해석은 원본과 동일한 3형태다.

형태 동작
"!command" 셸 실행 후 stdout (요청마다 실행, 캐시 없음)
"ENV_NAME" 그 환경변수 값이 있으면 사용
그 외 리터럴

compat 플래그

키 효과
supportsDeveloperRole false → developer 대신 system 역할 전송 (vLLM/SGLang 권장)
supportsReasoningEffort false → reasoning_effort 미전송
supportsUsageInStreaming 기본 true → stream_options.include_usage
maxTokensField max_tokens | max_completion_tokens
requiresToolResultName 툴 결과에 name 필드 추가
thinkingFormat qwen-chat-template → chat_template_kwargs.enable_thinking, qwen → 최상위 enable_thinking

7.3settings.json#

키 기본값 비고
defaultProvider / defaultModel –
defaultThinkingLevel – off|minimal|low|medium|high|xhigh|max

9.1계약#

my-skill/
├── SKILL.md                       프론트매터에 name, description 필수
├── pyproject.toml                 ← 이 파일의 존재가 Python 스킬임을 표시
└── src/
    └── my_skill/
        └── __init__.py            run() 이 있으면 모듈이 async callable 이 된다

4조건이 전부 성립해야 한다. 하나라도 어긋나면 경고와 함께 마크다운 전용으로 강등된다.

  1. SKILL.md 존재 (description 없으면 아예 로드 안 됨)
  2. 루트에 pyproject.toml
  3. import 이름 = 스킬명의 하이픈→언더스코어, 유효한 Python 식별자
  4. src/<import_name>/__init__.py

추가 규칙:

  • name 은 부모 디렉터리명과 일치해야 한다 (아니면 경고)
  • [project.scripts] 이름은 import 이름과 정확히 일치 (word_count, word-count 아님)
  • hatchling 사용 시 [tool.hatch.build.targets.wheel] 필수

9.3폐쇄망에서 pip 없이 로드#

이식본은 각 Python 스킬의 src 디렉터리를 커널 sys.path 에 직접 넣는다. pip install -e 없이 import 되므로 폐쇄망에서 설치 단계가 하나 줄어든다.

# skills.py
def src_paths(skills) -> str:
    return os.pathsep.join(str(s.root / "src") for s in skills
                           if s.python and (s.root / "src").is_dir())

외부 의존성이 있는 스킬(예: attach-image → pillow)만 wheelhouse 에서 설치하면 된다.

10세션 포맷#

원본 docs/session-format.md 의 version 3 과 호환된다.

{"type":"session","version":3,"id":"uuid","timestamp":"...","cwd":"/path"}   // 헤더
{"type":"message","id":"a1b2c3d4","parentId":"prev1234","timestamp":"...","message":{...}}
{"type":"model_change",...,"provider":"internal","modelId":"Qwen3-32B"}
{"type":"compaction",...,"summary":"...","firstKeptEntryId":"c3d4e5f6","tokensBefore":50000}
{"type":"branch_summary",...,"fromId":"f6g7h8i9","summary":"..."}
{"type":"custom",...,"customType":"prime-agent.refinement","data":{...}}
{"type":"session_info",...,"name":"세션 이름"}
{"type":"child_usage_attributed",...,"targetId":"...","childUsage":{...},"aggregateUsage":{...}}
  • 엔트리 id 는 8자리 hex, 첫 엔트리 parentId 는 null
  • 현재 위치 = 활성 leaf, 브랜치는 이전 엔트리에서 새 자식을 만드는 것
  • 손상된 줄은 건너뛴다 (한 줄이 세션 전체를 막지 않게)

컨텍스트 구성 (build_context()): leaf→root 경로를 모으고, 경로에 compaction 이 있으면 요약 먼저 → firstKeptEntryId 부터 compaction 까지 → compaction 이후 순으로 배치한다. 부기 엔트리(child_usage_attributed, label, session_info)는 제외된다.

14.1가장 큰 실질적 차이#

데몬이 없으므로 터미널을 닫으면 세션이 끝난다.

세션 JSONL 은 계속 남으므로 pa -r <id> 로 언제든 이어갈 수 있다. 백그라운드 상주가 필요하면 다음 중 하나를 쓴다.

  • Windows: 작업 스케줄러 또는 NSSM 으로 서비스 등록
  • Linux: systemd --user 유닛 또는 screen/tmux
  • 또는 §13 의 "데몬화" 확장 포인트를 직접 구현

15보안 — 원본과 동일하게 샌드박스가 아니다#

커널은 모델이 만든 Python 을 호스트와 같은 OS 권한으로 실행한다. 프로세스 분리는 라이프사이클 격리이지 권한 격리가 아니다.

항목 권고
실행 계정 전용 저권한 계정
실행 위치 일회용 클론 / 깨끗한 worktree
격리 진짜 격리가 필요하면 외부 샌드박스(컨테이너·전용 VM)를 바깥에
신뢰 코드 스킬·Python 패키지는 전부 신뢰 코드. 사내 검토 절차를 태울 것
데이터 커널이 접근 가능한 파일 = 모델에 보낼 수 있는 파일
autonomous 게이트 없이 쓰지 말 것
기록 세션 JSONL 과 하네스는 대화 원문을 그대로 담는다. 보존·파기 정책 필요

호스트 브리지는 loopback(127.0.0.1) 에만 바인딩하고 랜덤 포트 + 32자 토큰으로 인증하지만, 같은 머신의 같은 사용자에 대한 방어는 아니다. 원본의 하드닝과 같은 수준이다.
