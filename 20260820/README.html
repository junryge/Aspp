S3 Manager 사용설명서

AWS S3 와 사내 S3 호환 스토리지(MinIO 등)를 한 화면에서 다루는 데스크톱 파일 관리 도구. 디렉토리 생성, 업로드·다운로드, 재귀 삭제.

개요

S3 는 CLI 로 다루면 빠르지만, 여러 명이 쓰는 로그·산출물 버킷은 눈으로 보면서 만지는 편이 사고가 적습니다. 이 도구는 탐색기와 같은 조작감으로 버킷을 다루되, 내부 동작은 전부 로그창에 남깁니다.

코어 로직(s3_core.py)과 화면(s3_manager.py)이 완전히 분리되어 있어, GUI 없이 배치 스크립트에서 S3Core 만 import 해서 쓸 수도 있습니다.

폐쇄망 반입

외부망에서 wheel 을 먼저 받아둔 뒤 내부망에서 오프라인 설치합니다.

# 외부망
pip download boto3 PyQt5 -d ./wheels

# 내부망
pip install --no-index --find-links=./wheels boto3 PyQt5

PyQt5 반입이 막혀 있다면 PySide6 만 있어도 그대로 돌아갑니다. s3_manager.py 상단의 호환 레이어가 import 시점에 자동 분기하며, QAction 위치 차이(PyQt5 는 QtWidgets, PySide6 는 QtGui)까지 처리합니다.

접속 설정

툴바 [연결] 을 누르면 접속 다이얼로그가 뜹니다. 핵심은 Endpoint URL 한 칸입니다.

항목비웠을 때채웠을 때
Endpoint URLAWS S3 로 접속. Region 기준, virtual-hosted 주소 방식사내 S3 호환 스토리지로 접속. 예: http://10.20.30.40:9000
Path-styleauto (AWS 기본)자동으로 켜짐 — MinIO 계열은 이게 맞습니다

나머지 항목

  • Region — AWS 면 ap-northeast-2 등. 호환 스토리지는 아무 값이나 무방하나 us-east-1 권장
  • Access Key / Secret Key — 필수
  • Session Token — STS 임시자격증명을 쓸 때만
  • SSL 인증서 검증 — 사설 인증서 환경이면 체크 해제 (verify=False)
  • 프로파일로 저장 — ~/.s3gui/profiles.json 에 저장, 파일 권한 0600

Secret Key 저장에 관해. 프로파일에 저장되는 Secret Key 는 base64 인코딩만 되어 있습니다. 암호화가 아닙니다. 어깨너머 노출을 막는 수준일 뿐이고, 파일을 읽을 수 있는 사람은 그대로 복원할 수 있습니다. 보안 등급이 높은 망에서는 저장 체크를 끄고 매번 입력하십시오.

  • 다중 선택 — 우측 목록에서 Ctrl / Shift 클릭. 파일과 폴더를 섞어도 됩니다
  • 우클릭 메뉴 — 다운로드 / 삭제 / 키(Key) 클립보드 복사 / 새로고침

S3 에는 디렉토리가 없다

S3 는 flat key-value 스토어입니다. a/b/c.txt 의 / 는 계층 구조가 아니라 그냥 키 문자열의 일부입니다. 이 도구는 두 가지 방법으로 디렉토리를 흉내냅니다.

  • 조회 — list_objects_v2(Delimiter='/') 가 돌려주는 CommonPrefixes 를 폴더로 표시
  • 생성 — a/b/ 라는 0바이트 객체(폴더 마커)를 넣어 빈 폴더도 눈에 보이게 함

덕분에 빈 폴더 생성 → 파일 업로드 → 폴더 삭제 가 파일시스템처럼 자연스럽게 동작합니다. 다른 도구가 만든 폴더에는 마커가 없을 수 있는데, 그런 경우에도 하위에 객체가 하나라도 있으면 CommonPrefixes 로 잡히므로 트리에 정상적으로 나타납니다.

목록 표시에서 폴더 마커 자기 자신과 / 로 끝나는 키는 파일 목록에서 걸러냅니다. 그래서 폴더 안이 실제로 비어 있으면 화면에도 비어 보입니다.

문제 해결

증상원인과 조치
SignatureDoesNotMatchSecret Key 오타가 가장 흔합니다. 키가 맞다면 시스템 시계가 틀어진 경우도 있으니 서버 시각을 확인하십시오
SSLError / CERTIFICATE_VERIFY_FAILED사설 인증서 환경입니다. 접속 설정에서 SSL 인증서 검증 체크를 해제하십시오
버킷 이름이 도메인처럼 붙어 실패virtual-hosted 주소로 접속 중입니다. Path-style 주소 강제 를 체크하십시오
EndpointConnectionErrorEndpoint URL 의 스킴(http/https)과 포트를 확인하십시오. 프록시 환경이면 NO_PROXY 에 내부 대역을 넣어야 할 수 있습니다
InvalidLocationConstraintMinIO 등이 CreateBucketConfiguration 을 거부하는 경우로, 코어가 자동으로 재시도합니다
한글 파일명이 깨짐키는 UTF-8 로 저장됩니다. 상대 도구가 다른 인코딩을 쓰는지 확인하십시오

주의사항

삭제는 복구되지 않습니다. 특히 디렉토리 삭제는 prefix 하위 전체를 재귀로 지웁니다. 확인창에서 대상 목록을 반드시 눈으로 확인하십시오.

  • 버저닝 버킷 — 버저닝이 켜져 있으면 delete_object 는 delete marker 만 남기고 이전 버전은 그대로 유지됩니다. 완전 삭제가 필요하면 list_object_versions 기반 로직을 추가해야 합니다.
  • 멀티파트 임계값 — boto3 기본값(8MB)을 사용합니다. 회선이 느리거나 대용량 위주라면 s3_core.py 의 upload_file 에 TransferConfig(multipart_threshold=..., max_concurrency=...) 를 지정해 조정하십시오.
  • 취소 동작 — 취소는 진행 중인 개별 파일 전송이 끝나는 지점에서 반영됩니다. 이미 올라간 파일은 남으므로, 필요하면 수동으로 정리하십시오.
  • 권한 — 기능별로 ListBucket, GetObject, PutObject, DeleteObject 권한이 필요합니다. 버킷 생성/삭제까지 쓰려면 CreateBucket, DeleteBucket 도 있어야 합니다.
